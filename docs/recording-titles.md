# Recording titles from summaries

Completed summaries name audio recordings with the existing concise AI title (three to six words, up to 60 characters). Browser/desktop imports, recorder sync and live captures initially receive a placeholder display name. That default is eligible for replacement by the title returned with the summary, including summary-only jobs that reuse the saved transcript. Titles explicitly renamed in the app or chosen from a calendar event remain manual and are preserved. A manual rename made while a summary runs also wins at completion.

Schema 17 repairs only title provenance for existing affected server uploads: when a completed upload's original filename exactly matches its recording title, the title becomes a replaceable placeholder. The old import path marked those default filenames as manual. It also recognizes linked completed live/interrupted captures with the original automatic timestamp label and no manual provenance. Distinct custom titles, AI titles, unknown provenance, unlinked recordings and unfinished uploads remain untouched. Older data cannot distinguish an automatic filename from a filename deliberately restored by a user; that exact-filename case becomes eligible too. Manual filename edits made after the upgrade remain protected, including across restarts.

The upgrade does not change displayed titles, saved summaries, transcript words, audio paths, device filenames, processing jobs or model selections, and starts no new AI requests. Currently queued summaries can name eligible recordings when they complete. For an already finished recording still using its filename, choose Resummarize; it reuses the saved transcript without retranscribing. Old generated title responses were not stored separately, so they cannot be recovered without another summary request.

The existing pre-migration SQLite recovery copy preserves schema-16 data. Table/column definitions do not change, but the schema version advances to 17 to make this a one-time atomic repair and to protect later manual edits. Older backups still restore and migrate through the normal flow. A downgrade needs the pre-upgrade copy or another compatible backup.
